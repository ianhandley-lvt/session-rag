# Authority is a ranking-time computation, not a stored field

Both the original design brief and the first implementation modeled `authority` as a fixed enum stored on each record (`working_session` / `verified_decision` / `unknown`), conflating three separate things: where evidence came from (Source Type — immutable), whether it's been reviewed (Verification Status — mutable lifecycle), and how much a piece of evidence should outrank another during retrieval (Authority). We rejected the stored enum because a Claude session doesn't become a different source type when someone verifies an episode, and an external document isn't automatically authoritative merely for being external — collapsing these into one field made illegitimate combinations easy to write and correct ones (e.g. "verified, but still just a working session") impossible to express.

Authority is instead computed during retrieval from Source Type, Verification Status, Temporal Scope, and recency, versioned/configurable so ranking changes stay testable. If a future need arises for an explicit human-managed trust tier independent of verification, it should be a new field (e.g. `informal | supporting | canonical`), not a repurposing of `authority`.
